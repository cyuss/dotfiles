01L'architecture du shell

Le principe directeur : rien de coûteux au démarrage. Sur une machine où l'on ouvre un pane herdr par tâche, chaque milliseconde du .zshrc est payée des dizaines de fois par jour.

Qui lit quoi

fichierlu parcontenu
~/.zshenvtous les shells, y compris non interactifs — scripts Emacs, herdr, launchd, zsh -cPATH et variables d'environnement. Rien d'autre ne doit y aller, et rien de tout cela ne doit être ailleurs
~/.zshrcles shells interactifsprompt, plugins, complétion, raccourcis, intégrations
~/.config/zsh/aliases.zshsourcé par .zshrcalias et fonctions — versionné avec le reste de la config
~/.config/zsh/completion.zshsourcé par .zshrc, après compinitles trois couches de complétion (section 03)
~/.config/zsh/completions/ajouté au fpath avant compinitcomplétions générées par les outils eux-mêmes

L'ordre de chargement — il est contraignant

  1. Prompt — oh-my-posh, thème amro
  2. antidote (fpath) — les plugins qui n'apportent que des complétions. Obligatoirement avant compinit
  3. fpath des complétions générées — ~/.config/zsh/completions. Même contrainte : compinit ne relit pas le fpath une fois passé
  4. compinit — le dump n'est revérifié qu'une fois par jour ; sinon compinit -C, qui saute la vérification de sécurité
  5. antidote (plugins) — les plugins normaux. Après compinit : fzf-tab l'exige
  6. completion.zsh — carapace, fzf-tab, autosuggestions. Après compinit et après les plugins
l'erreur qui coûte le plus cherPlacer le fpath=(…) des complétions générées dans completion.zsh plutôt que dans .zshrc. completion.zsh est sourcé après compinit : les fichiers _uv, _ruff, _herdr sont bien là, mais plus personne ne les regarde. Aucun message d'erreur — juste une complétion qui ne répond pas.
antidote plutôt qu'antigenantigen n'est plus maintenu depuis 2021. antidote génère un fichier statique (~/.zsh_plugins.zsh), régénéré uniquement si la liste a changé : le coût au démarrage est celui d'un simple source, pas d'une résolution de dépendances.

02Le démarrage

Environ 310–340 ms. Ce chiffre est le résultat d'un travail précis : les gestionnaires de versions coûtaient à eux seuls 750 ms par shell.

Chargement paresseux

outilcoût évitémécanisme
nvm593 ms par shellnode, npm, npx, yarn, pnpm, corepack sont des fonctions qui, au premier appel, se suppriment, sourcent nvm et se relancent. Le binaire est dans le PATH tout de suite
jenv153 ms par shellmême schéma ; les shims Java sont déjà dans le PATH
chruby—même schéma, sur ruby, gem, bundle, rake
carapaceun sous-processus par shelll'initialisation est écrite dans ~/.cache/carapace-init.zsh et régénérée seulement si le binaire est plus récent
pyenv—chargé normalement : un seul eval, qui gère aussi le PATH
condaretiréuv fait le travail. L'installation existe toujours (~/miniconda3, 7,9 Go)

jamais --force nugpf est push --force-with-lease. La différence n'est pas cosmétique : --force écrase la branche distante sans regarder, --force-with-lease refuse si quelqu'un a poussé depuis ta dernière récupération. C'est la seule forme de force acceptable sur une branche partagée.

Sur une branche de review où l'on corrige dix remarques, cela remplace dix rebase -i manuels.
