01Le modèle mental

herdr est un gestionnaire d'espaces de travail conçu autour des agents. Ce n'est pas « tmux avec des couleurs » : le serveur connaît l'état de chaque agent et sait lequel t'attend.

A
serverUn processus. Il survit à la fermeture du terminal ; tout est restauré à la reconnexion.
B
spaceUn contexte de travail complet. En pratique : un projet. Porte sa branche git et son état.
C
tabUne disposition de panes à l'intérieur d'un space. Se nomme tout seul.
D
paneUn terminal. Peut héberger un agent, que herdr surveille.

Ce qui distingue herdr d'un multiplexeur classique

capacitéce que ça change concrètement
États d'agentLe serveur sait si un agent travaille, attend une réponse, est inactif ou a fini. La sidebar les trie, et une notification macOS native arrive quand l'un d'eux te bloque.
Sidebar structuréeDeux panneaux : les spaces (avec branche git et statut) et les agents (avec contexte consommé et quota restant). Aucune commande à taper pour savoir où en est le travail.
PluginsUn vrai système d'extensions avec actions bindables. 21 sont installés ici — navigator, reviewr, memex, usagebar, floax…
Templates déclaratifsUn fichier TOML par projet décrit tabs, panes et commandes de démarrage. Le space se monte entier en une touche.
Worktrees gitUn space peut être adossé à un worktree dédié, pour faire travailler un agent sans polluer ta copie de travail.
le geste centralCtrl+b w — le navigator. Quand on ne sait pas où est la chose (un space, un agent, une session, un projet), c'est toujours la bonne touche. Tout le reste de ce document en découle.

02La grammaire des touches

Le préfixe est Ctrl+b. Cette configuration s'écarte des défauts herdr sur un point de principe : aucune majuscule dans les gestes quotidiens.

Le principe

règleexemplepourquoi
La lettre = le motprefix+n = new, prefix+c = create, prefix+w = whereaucune table à mémoriser : le nom de l'action donne la touche
Pas de Shiftles paires vont sur des touches voisines : [ ], , .le défaut herdr mettait next_tab sur prefix+n et new_workspace sur prefix+shift+n — deux actions très différentes sur la même lettre, dont une avec Shift
Alt = varianteprefix+g lazygit en popup, prefix+alt+v en pane latéralle second niveau, pour tout ce qui est outil plutôt que navigation
Sans préfixe = traversantalt+h alt+j alt+k alt+ltraverse les panes herdr et les splits Neovim de façon continue

Les six familles

familletouchescontenu
Spacesn [ ] / ' gcréer, parcourir, renommer, fermer, choisir
Tabsc , . ; 1..9créer, parcourir, renommer, aller au n°N
Paness v i j k l x zdiviser, se déplacer, fermer, zoomer
Agentsalt+, alt+. alt+1..9parcourir, sauter au n°N
Navigationw alt+w alt+i p hnavigator, projets, space quotidien
Outilsalt+g alt+d alt+b alt+k alt+mgit, docker, système, processus, docs
touches à ne jamais utiliser dans un pickerCtrl+s est XOFF : le terminal gèle son affichage jusqu'à un Ctrl+q (XON). C'est exactement le bug qui faisait « disparaître » le texte du navigator pendant la frappe. Sont également piégés : Ctrl+q (XON), Ctrl+c (SIGINT), Ctrl+z (SIGTSTP), Ctrl+d (EOF). Vérifier avec stty -a : la ligne stop = ^S confirme que ixon est actif.

les tabs se nomment tout seulsprompt_new_tab_name et prompt_new_workspace_name sont à false : rien ne demande de nom à la création. Le plugin herdr-automatic-rename nomme le tab d'après ce qui y tourne. hide_tab_bar_when_single_tab fait disparaître la barre quand il n'y a qu'un onglet — donc, dans un space à un seul tab, aucun chrome inutile.

Le space quotidien

Tout ce qui n'appartient à aucun projet : l'état des dépôts, le système, les fichiers, les mises à jour. Une seule touche — prefix+h — et il apparaît ou reprend le focus.

pourquoi un script et pas la commande directeherdr-plus open crée toujours un nouveau space (workspaceCreate) : appuyer deux fois donnait deux « quotidien ». Le binding passe donc par herdr-open-project quotidien, qui focalise l'existant s'il est là. Le chemin est absolu dans la config : un binding type = "shell" tourne détaché et n'hérite pas forcément du PATH du shell de connexion.

Le point d'entrée universel. Un seul picker flou pour les spaces, les agents, les sessions, les serveurs, les plugins et les projets — avec des filtres pour restreindre la portée.

Les filtres

touchefiltrece qu'on y trouve
Ctrl+wworkspacetous les spaces ouverts, avec leur branche
Ctrl+aagenttous les agents, avec leur état

le filtre Ctrl+N ne s'appelait « plugin » que par accidentIl montre la source Source::Integration, c'est-à-dire les blocs [[integrations]] de la config du navigator — pas les plugins herdr. D'où l'impression qu'il n'y contenait que la gestion des spaces. Une intégration actions y verse maintenant les 61 actions réellement exposées par les 20 plugins (herdr plugin action list). Les actions du navigator lui-même en sont retirées — les invoquer depuis le navigator ouvrirait un navigator dans le navigator. Autre chemin vers la même chose : prefix+a, la palette de commandes.
pourquoi ces lettres et pas les initialesLe schéma « initiale de la catégorie » plaçait les sessions sur Ctrl+s. Or Ctrl+s est XOFF : le terminal gelait son affichage et le texte semblait disparaître pendant la frappe. Les sessions sont donc sur Ctrl+l et les serveurs sur Ctrl+g.

Créer, renommer, supprimer depuis le navigator

  1. Ouvrir le navigator : prefix+w
  2. Taper un nom qui n'existe pas encore — l'entrée create apparaît en bas de liste
  3. RET lance herdr-nav-create, qui demande le type (space, session, quick) puis monte l'objet via herdr-new
  4. Pour renommer ou supprimer : Ctrl+n sur l'entrée choisie, ou le popup dédié prefix+alt+e (herdr-manage)

La vue arborescente — les tabs sous leur space

Comme choose-tree dans tmux : les tabs d'un space apparaissent comme lignes enfant, dans la section open, juste sous lui.

open   [3] project: mon-garage-auto      2 tabs · 3 panes
open     ├ agent                         tab 1
open     └ run                           tab 2 · 2 panes
détailcomment ça marche
L'ordreles lignes enfant sont insérées juste après leur space. Le tri du picker retombe sur l'ordre d'insertion à score égal — c'est ce qui fait tenir l'arbre à requête vide
La recherchele libellé du space est dans le haystack de chaque tab : taper le nom du space fait remonter le space et ses tabs
Ctrl+Xsur une ligne enfant, ferme le tab — pas le space. Sans ce garde-fou, viser un tab fermerait tout ce qu'il contient
Spaces à un seul tabpas d'enfant : l'unique tab ferait doublon avec la ligne du space. tab_children_min = 1 les affiche quand même
La numérotationla ligne enfant affiche la position (« tab 2 »), pas le champ number. number est un compteur de création qui garde les trous des tabs fermés : un space où l'on a fermé un tab affiche [2] sur un tab dont number vaut 4. Et switch_tab = "prefix+1..9" est une liaison indexée — elle vise la position
Désactivertab_children = false dans [picker]
c'est un correctif local du plugin, pas une option d'origineUne [[integrations]] ne peut pas produire ce résultat : le plugin n'interprète kind que pour server / remote-terminal (→ Source::Server) et session (→ Source::Session) ; tout le reste tombe dans Source::Integration. Aucun chemin ne mène à la section open. Le correctif est dans ~/.config/herdr/patches/. Une mise à jour du plugin l'écrase — le README y donne les trois commandes pour le réappliquer. En cas d'échec, le plugin d'origine fonctionne normalement, sans l'arborescence.
les sessions ne sont pas imbriquées, et ce n'est pas un oubliUne session est un serveur herdr séparé, pas un enfant d'un space : elle a sa propre fenêtre et son propre jeu de spaces. L'imbriquer serait faux. Elle garde son filtre, Ctrl+L. La hiérarchie réelle est session → space → tab → pane ; le navigator en montre maintenant deux niveaux d'un coup.
sources désactivéeszoxide, roots et quick sont éteints dans herdr-navigator/config.toml : ils noyaient la liste sous des chemins récents sans rapport avec le travail en cours. Les projets sont placés en dernier dans source_order, pour que les spaces réellement ouverts remontent en tête. zoxide reste accessible séparément sur prefix+alt+z.

C'est la raison d'être de herdr : savoir, sans rien taper, quel agent te bloque.

Le panneau agents

Règle appliquée : une idée par ligne, la plus importante en premier. La disposition précédente mettait state_icon, workspace et tab sur une seule ligne de 24 colonnes — tout était tronqué, et le projet, l'information la plus utile, était le premier sacrifié.

◐ refactor du panier      état + tâche en cours
  mon-garage-auto         DANS QUEL PROJET
  run                     où exactement dedans
  ⛁ 13%   5h 72%          ce qu'il consomme
famillejetons
Built-ins herdrstate_icon · state_text · workspace · tab · pane · agent · terminal_title · terminal_title_stripped
Métadonnées de paneles jetons en $, publiés par un plugin via herdr pane report-metadata
Style en ligne{ token = "workspace", fg = "#ffc799", bold = true, dim = true } — seuls #RGB et #RRGGBB sont acceptés, pas de noms de couleur
il n'existe pas de jeton « dossier »La liste ci-dessus est complète. Pour savoir d'où vient un agent, c'est workspace qui répond — le libellé du space. C'est pourquoi prefix_workspace_labels est passé à false : le préfixe project: mangeait 9 colonnes sur chaque libellé. Le changement ne vaut que pour les nouveaux spaces ; renommer un space existant se fait avec prefix+/.

Fournis par le plugin usagebar. Ils ne s'affichaient nulle part : le plugin tournait, calculait tout, et n'avait aucun emplacement dans les lignes de la sidebar.

Worktrees git

Répertoire : ~/.herdr/worktrees. Un worktree donne à un agent une copie de travail à lui, sur sa propre branche — il peut donc modifier des fichiers pendant que tu travailles sur les mêmes, sans conflit et sans stash.

toucheaction
prefix+shift+gcréer un worktree et le space qui va avec
prefix+dreviewr — relire ce que l'agent y a fait avant de fusionner

jj (Jujutsu) — colocalisé avec git

jj vit dans le même dépôt que git : les deux outils voient les mêmes commits, on peut alterner sans rien migrer. Utile ici parce que jj n'a pas de zone de staging — chaque modification est déjà « dans » le changement courant, ce qui colle au rythme d'un agent qui écrit en continu.

commandeeffet
jj llog — l'arbre des changements
jj ddiff du changement courant
jj sstatut
jj ci -m "…"décrire le changement et en commencer un nouveau
jj into <rev>déplacer le travail courant dans une révision existante
jj outextraire le travail courant vers un nouveau changement
gdtgit dft — diff syntaxique difftastic, le même moteur que jj
les alias jjfix entrait en conflit avec la commande intégrée du même nom : l'alias a été renommé into. Le formateur de diff est difftastic, qui compare les arbres syntaxiques au lieu des lignes — sur un reformatage, il montre ce qui a vraiment changé.
